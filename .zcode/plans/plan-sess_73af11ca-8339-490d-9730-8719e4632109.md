# Строгий тип `name` для иконок

## Суть

`Ionicons` из `@expo/vector-icons` уже типизирован юнионом ~1300 литеральных имён глифов (`Icon<GlyphUnion, 'ionicons'>`). Паттерн `ComponentProps<typeof Ionicons>['name']` уже используется в `bottom-tab-bar.tsx` — выносим его в `icon.tsx` как публичный `IconName` и убираем `string` во всех потребителях. Опечатка в имени иконки станет ошибкой компиляции.

## Изменения

1. **`shared/ui/icon/icon.tsx`**:
   - `export type IconName = ComponentProps<typeof Ionicons>['name']`;
   - база пропсов: `Omit<ComponentProps<typeof Ionicons>, 'color'>` вместо глубокого импорта `IconProps<string>` из `@expo/vector-icons/build/createIconSet` (deep-import уходит, `name` наследуется строгим);
   - убрать касты `as any` у `name`/`color` (типы теперь совпадают); кастомные `colorClassName`/`color`/`className` — без изменений.
2. **Баррел `icon/index.ts`**: экспортировать `IconName`.
3. **Потребители — заменить `string` на `IconName`**:
   - `input.tsx`: `leadingIcon?`/`trailingIcon?`;
   - `icon-button.tsx`: `icon`;
   - `quick-actions-row.tsx`: `ACTIONS[].icon`;
   - `mock-data.ts`: `MockCategory.icon` (импорт из `@/shared/ui/icon` — model→shared допустимо по FSD);
   - `expenses-sheet.tsx`: `ExpenseRowView.categoryIcon`;
   - `bottom-tab-bar.tsx`: удалить локальный `type IconName = ComponentProps<typeof Ionicons>['name']` и ставшие ненужными импорты (`Ionicons`, `ComponentProps`) — импортировать `IconName` из `@/shared/ui/icon` (единый источник).
   - `selectors.ts` (`category?.icon ?? 'pricetag-outline'`) — тип выведется сам, правки не нужны.

## Верификация

- `pnpm type-check` — главное: tsc проверит все существующие имена (в т.ч. в mock-данных: `car`, `cafe`, `paw`, `cart`, `cash` — все валидны);
- `pnpm lint` + `pnpm test` (57);
- sanity: временная опечатка не нужна — доверяем tsc на литералах в JSX.

Поведение рантайма не меняется — чисто типизация.
